For agents that trade on Elysium and HyperCore

The fill is graded before the next order is allowed.

An agent commits to a route and its expected cost before it acts. When the fill lands, RouteClerk writes an Autopsy that compares what was promised against what actually happened — and blocks the next order until the deviation is acknowledged or covered.

Once the HyperCore market-data precompile and ElysiumCoreWriter open a 100–200 ms path, speed stops being the constraint. Hidden cost becomes the expensive failure. RouteClerk makes that cost enforceable before the agent is allowed to act again.

One promise, one audit, four moves.

Commit the route

Before any order intent is accepted, the agent locks a route and its expected all-in cost in basis points, with a deadline. The commitment is hashed and stored so it cannot move after the fact.

Let the fill land

The order executes through the ElysiumCoreWriter path on the user's own HyperCore account. Custody never leaves the user; RouteClerk holds no funds and cannot withdraw.

Write the Autopsy

Realized cost is graded against the commitment: entry versus mid, fees, funding and position drift. The result is a signed receipt, comparable across the Elysium AMM and HyperCore.

Gate the next action

A deviation inside tolerance clears the agent. A breach blocks the next intent until the Autopsy is acknowledged or the deviation is covered with a bond — freeing it for a specialist to challenge.

Native to the venue, not bolted onto it.

Reads the real book

Commitments are priced against the HyperCore market-data precompile — full depth, not a proxy feed — so the expected cost is the cost the venue will actually charge.

Writes on the real path

The gate sits in front of ElysiumCoreWriter's 100–200 ms write path. The check is one call; it never adds a hop to execution, only a condition.

Comparable everywhere

Because commitments and Autopsies are on-chain, Elysium AMM and HyperCore fills can be scored on the same ledger — by the operator, by the user, and by any specialist paid to challenge a number.

Four functions do the whole job.

The gate is deliberately small. An agent's order path asks one question before it fires, and the answer is on-chain.

// 1. the agent promises a route and a cost
submitCommitment(id, routeHash, expectedCostBps, sizeUsd, deadline)

// 2. the order path asks one question before it acts
canAct(agent)  // true unless a failed autopsy is open

// 3. the Clerk files the autopsy after the fill
submitAutopsy(id, commitmentId, realizedCostBps, fundingDriftBps, thresholdBps)

// 4. unblock: acknowledge, or cover the deviation
acknowledgeAutopsy(id)  /  coverDeviation(id)  payable
